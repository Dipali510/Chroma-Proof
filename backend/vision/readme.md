# ChromaProof - Role 1: Computer Vision & Classification

> **PROTOTYPE / DEMO image-processing pipeline. Not validated forensic or toxicology software.**
> Every output is a *presumptive* result. It is not a drug identification, laboratory confirmation,
> legally admissible evidence or validated forensic identification. Laboratory confirmation is required.
> Thresholds were tuned on **synthetic** images only.

## Project layout (10 files)
```
vision/
  __init__.py     public API (process_image, process_image_detailed, DEFAULT_CONFIG)
  config.py       ALL thresholds, card/ROI geometry, rules, confidence limits, version
  models.py       data models/schema + colour-space helpers (RGB->LAB/HSV, dE76, glare mask)
  quality.py      blur / exposure / glare checks + reference-card detection and rectification
  calibration.py  colour calibration from card patches + reagent ROI extraction/features
  classifier.py   deterministic dE76 rules (R1-R4) + heuristic confidence
  processor.py    process_image(image) integration function, input validation, CLI
  synthetic.py    synthetic demo-image generator + sample-data/example-output writer
  README.md       this file
tests/test_vision.py   all unit tests (quality, calibration, classifier, processor)
```
Sample images are not stored; generate them (synthetic, non-sensitive) with one command - see "Sample data".

## What Role 1 does
`process_image(image)` takes a test-kit photo and: (1) runs a quality gate, (2) finds and rectifies the
reference colour card, (3) calibrates colour from the card's patches, (4) extracts the reagent ROI,
(5) applies deterministic demo rules and returns Positive / Negative / Inconclusive with a plain-language
explanation. No machine learning, no network, no secrets.

## Input
Encoded image bytes (JPEG/PNG...), a file path, or an 8-bit BGR/BGRA array (as from `cv2.imread`).
Colour image required, shortest side >= 300 px. Invalid / empty / corrupted / greyscale / 16-bit input is
rejected with a reason - never classified.

## Output (stable contract)
```json
{
  "quality_status": "PASS | RETAKE | ERROR",
  "quality_reasons": ["..."],
  "result": "Positive | Negative | Inconclusive",
  "confidence": "High | Medium | Low",
  "explanation": "...",
  "version": "chromaproof-vision-0.1.0"
}
```
* `RETAKE`: image unsuitable; `result` is `Inconclusive`, `confidence` is `Low`, reasons say what to fix.
* `ERROR`: only for an unexpected internal exception (still `Inconclusive`, never a fake result).
* `confidence` is a **heuristic indicator, not a probability** that a substance is present.
* `process_image_detailed(image).to_debug_dict()` adds intermediate values; the stable contract is the six fields.

## Pipeline
| Step | Where | Notes |
|---|---|---|
| Load/validate | `processor.py` | bytes/path/array, size, dtype, greyscale checks |
| Quality gate | `quality.py` | blur, exposure, glare, card visible/cropped; **all reasons collected** |
| Card detection | `quality.py` | edge + dark-border contours -> convex 4-corner quad, aspect/angle checks, perspective warp |
| Calibration | `calibration.py` | per-channel gain/offset from patches; outlier rejection; explicit failure |
| ROI | `calibration.py` | configured window on rectified card; glare/shadow excluded; median LAB/HSV |
| Classifier | `classifier.py` | deterministic dE76 rules R1-R4 |
| Config | `config.py` | every threshold in one place |

### Quality checks
* **Blur**: variance of the Laplacian on the (<=800 px) grey image; `quality.blur_threshold` (demo value 100, prototype only).
* **Exposure**: mean grey outside 50-215, or contrast std < 12. (Blur is not judged on a too-dark image.)
* **Glare**: HSV value >= 250 and saturation <= 40; limit 2% of the image and 1% of the card.
* **Card**: not found / cropped at image edge / patches occluded / unsupported layout -> `RETAKE`.
* **ROI**: too small, >30% glare/shadow, or non-uniform -> "Reagent region cannot be identified".

### Calibration approach
Median RGB of each of the 6 reference patches (white, 2 greys, red, green, blue) is fitted to its nominal
sRGB value with a per-channel linear model `corrected = gain*observed + offset`. The worst patch (CIELAB dE76)
is dropped until all remaining are within 15 dE; at least 5 must remain, mean residual must be <= 8 dE and gains
plausible, otherwise calibration **fails** and the image is a retake. This *reduces* but does **not eliminate**
lighting/camera bias (no gamma, white-balance or spectral model).

### Classification rules (CIELAB, dE76 to demo reference colours)
| Rule | Condition | Result |
|---|---|---|
| R1_OUTSIDE_RANGE | nearest reference > 30 dE | Inconclusive |
| R2_POSITIVE | dE(pos) <= 18 and beats negative by >= 10 | Positive |
| R3_NEGATIVE | dE(neg) <= 18 and beats positive by >= 10 | Negative |
| R4_BORDERLINE | otherwise | Inconclusive |

Demo references: positive = violet (110,50,140), negative = pale cream (235,225,185). They are **placeholders,
not validated reagent colours**. Confidence: High (dE <= 8, margin >= 30, calibration residual <= 5, ROI spread <= 6),
Medium (dE <= 14, margin >= 20), else Low.

### Demo card layout (assumption - configurable)
Landscape card, aspect ~1.5, thick near-black border, held roughly upright (<45 deg rotation, perspective ok).
After rectification to 600x400: 6 patches in a row at y=0.22 (x = 0.1375 + 0.145*i, half-size 0.055 x 0.10) and one
reagent window at (0.28,0.46)-(0.72,0.86), sampled in its central 60%. Change `CardConfig`/`RoiConfig` to adapt.

## Assumptions
Synthetic demo card and reagent colours; sRGB input in 8-bit BGR; one card and one reagent window per photo;
card roughly upright and fully in frame; JPEG/PNG inputs; Role 2 treats `ERROR` like a failed request.

## Known limitations
* Thresholds and rules are demo values - not validated on real kits, cameras, lighting or reagents.
* Works only for the configured demo card; unknown cards/kits are rejected or Inconclusive, not generalised.
* Whole-image blur score depends on scene texture/resolution; re-tune for real photos.
* Calibration is linear per channel; strong colour casts, mixed lighting, shadows or heavy JPEG compression may fail or bias it.
* A 180-degree-rotated or mirrored card is rejected (patch mismatch) rather than auto-corrected.
* Confidence is heuristic, not a probability. No claim of forensic accuracy is made.
